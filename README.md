## translate-ja-to-en-zh-tw

日本語のテキストを英語・簡体中文・繁体中文（台湾）へ翻訳する skill。

繁体中文を簡体中文からの字体変換で作ることを禁じ、日本語の原文から台湾の國語として訳し直すことを中心のルールにしている。字体変換では語彙が大陸のまま残るため（サーバーが 伺服器 ではなく 服務器 になる）、語彙・動詞の組み合わせ・儿化の有無・台湾の「會」用法まで言語ごとに訳し分ける。

出力は日本語・英語・簡体中文・繁体中文の 4 行からなる表。

### なぜ繁体中文のルールだけ厳しいのか

中文の学習データはネット上に存在する量がそのまま偏りになっていて、簡体中文が圧倒的に多い。そのため LLM に繁体中文を訳させると、繁体字に変換されてはいても中身は大陸の中文、という訳文が出やすい。

厄介なのは、これが一見すると正しく見えること。全ての文字が繁体字になっているので表記の誤りとしては検出できず、台湾人が読んで初めて「この語は使わない」と分かる。サーバーが 伺服器 ではなく 服務器 になっていても、繁体字である以上パッと見では気づけない。

さらに語彙だけでなく、次のような層でも大陸側に寄る。

- 動詞の組み合わせ: 地下鉄に乗る は 坐地鐵 ではなく 搭捷運
- 儿化: 大陸の 一点儿 に対し台湾は 一點
- 文法: 寒くない？ は 冷不冷？ ではなく 會不會冷？

そこで、繁体中文は簡体中文の訳を参照せず日本語の原文から訳し直すことを最上位のルールに置き、出力前の自己チェックと eval の両方で大陸語彙の混入を検出するようにしている。evals/ のケースが語彙・動詞・儿化・會用法に分かれているのは、この引っ張られ方が層ごとに別々に起きるため。

### インストール

マーケットプレイスを登録する。

```
claude plugin marketplace add koeda-ta/translate-ja-to-en-zh-tw
```

プラグインをインストールする。

```
claude plugin install translate-ja-to-en-zh-tw@translate-ja-to-en-zh-tw
```

### 使い方

翻訳したい日本語を渡す。

```
/translate-ja-to-en-zh-tw 今日は地下鉄に乗ってスーパーへ行き、じゃがいもを買いました。
```

「これを翻訳して」「英語と中国語にして」のように依頼した場合も、skill の description により自動で選択される。

## eval

evals/ に 16 件のテストケースがある。1 ケースが prompt.md（入力）と graders/criteria.md（合否の判定基準）の組で、判定は LLM が行う。

### 実行

```
claude plugin eval ./ --judge-model sonnet
```

--judge-model sonnet は必須。judge の既定は haiku だが、criteria.md は 軟體 と 軟件 のような語彙の可否を細かく判定するため、haiku では誤判定する。sonnet では 16 件全て合格し、skill なしでは全件不合格になる。

1 ケースだけ実行する場合はケース名を指定する。

```
claude plugin eval ./ --judge-model sonnet --case it-terms
```

主なオプションは次の通り。

| オプション | 用途 |
| ---------- | ---- |
| --case <名前> | ケースを絞り込む |
| -j <数> | 最大 8 並列で実行する |
| --no-publish | HTML レポートを公開せずローカルに留める |
| --trust-plugin | CI 向けに初回の信頼確認を省略する |

初回実行時は、プラグインをこのマシン上で実行してよいか確認を求められる。

実行結果は evals/results/ に出力される。このディレクトリは .gitignore に登録済み。

### ケース一覧

| ケース | 確認する内容 |
| ------ | ------------ |
| basic-vocab | 地域差のある基本語彙 |
| business-doc | 業務文書の文体 |
| country-names | 国名の音訳の違い |
| daily-life | 日常語彙 |
| education-admin | 教育・行政用語 |
| erhua-avoidance | 繁体中文で儿化を使わないこと |
| hongkong-terms | 香港の語彙を台湾の訳に混ぜないこと |
| it-terms | IT 用語の訳し分け |
| no-mixed-glyphs | 簡体字と繁体字が混在しないこと |
| proper-nouns | 固有名詞の表記 |
| spoken-hui | 台湾の「會」用法 |
| ui-labels | UI 文言の簡潔さ |
| ui-placeholder | プレースホルダの保持 |
| verbs-daily-service | 日常・サービス場面の動詞 |
| verbs-it-actions | IT 操作の動詞 |
| verbs-transport | 交通に関する動詞 |

### ケースを追加する

evals/ 配下にケース名のディレクトリを作り、次の 2 ファイルを置く。

- prompt.md: フロントマターに max_turns と allowed_tools を書き、本文に翻訳を依頼する日本語を書く
- graders/criteria.md: フロントマターに type: llm と weight を書き、本文に合否の判定基準を書く

判定基準は「この語は可、この語は不可」と具体的に列挙する。判定は LLM が行うため、基準が抽象的だと結果が安定しない。
